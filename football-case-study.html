01 / Question & contribution

From a football question
to an analytical workflow.

How are player characteristics associated with FIFA value, and how well can regression methods describe those relationships?

The original notebook collects player data from SoFIFA using Requests and BeautifulSoup, prepares it with pandas, explores relationships and compares linear, ridge, lasso and degree-two polynomial regression.

Completed as my dissertation for the MSc in Data Science and Computational Intelligence, the work combines data collection, cleaning, exploratory analysis and modelling in one notebook. This case study reviews its saved outputs; the models have not been rerun for this portfolio.

02 / Data preparation

Making scraped records usable.

Collect and structure

The scraper iterates through paginated player tables. Its saved output reports 9,080 raw rows and 8,842 after an initial deduplication step.

The cleaning code separates loan-related record formats, standardises field names and removes malformed entries.

Standardise and inspect

Heights are converted to centimetres, weights to kilograms, and value, wage and release-clause fields to numeric euro-million units. The cleaned dataset contains 8,480 records.

Exploration examines distributions, positions, clubs, ratings and correlations before modelling.

04 / Model review

Why I’m not leading with an accuracy claim.

The original notebook reports high R² scores. Reviewing the evaluation code reveals issues that need to be resolved before those results can support a claim about unseen players.

Separate test and validation data

Cell 62 creates a 20% test sample, then splits the full dataset again with the same random seed to create a 25% validation sample. The test observations are contained within the validation sample. They therefore do not form independent evaluation sets.

Keep feature transformations inside validation

The polynomial model is fitted on expanded features in cell 64, but the cross-validation call in cell 71 receives the raw features and a LinearRegression estimator without the polynomial transformation. That cross-validation result does not evaluate the same polynomial workflow.

Distinguish a financial proxy from a useful predictor

Release clause is extremely closely related to the target in this dataset. That is a proxy-risk concern, rather than proof of leakage. Comparing models with and without release clause and wage would help establish how much predictive information the player attributes add.

Interpretation: the saved outputs show promising relationships in a historical game dataset. They do not yet establish reliable forecasting performance or identify real-world transfer bargains.
05 / A stronger next version

What I would improve next.

01 / EVALUATION

Start with a clean split.

Create disjoint training, validation and test sets. Keep the final test set untouched until model selection is complete.

02 / COMPARISON

Build a fair benchmark.

Compare against a median-value baseline. Use pipelines for feature transformations and cross-validation, and compare financial-proxy versus player-attribute models.

03 / EXPLANATION

Understand the errors.

Report MAE in euro millions, examine errors by position and value band, and document the source snapshot, dependencies and reproducible steps.

These are proposed improvements, not completed experiments. The source repository is unchanged.
